# ADR-009: `shared_domain` — не God Package

**Статус:** Принято  
**Дата:** 2026-07-10

## Контекст

Риск создать `shared_domain` «на будущее» или перенести туда типы одной feature.

## Решение

Workspace-пакет `shared_domain` появляется **только** когда существует тип с **вторым независимым владельцем**.

### Ключевое различие

«Две feature используют тип» ≠ «тип общий».

Связь shell → game **не означает**, что тип уже общий. Тип может по-прежнему принадлежать shell и экспортироваться через StatePort без `shared_domain`.

### Правила

- в `shared_domain` — только типы с двумя **независимыми** владельцами (разные bounded context);
- **запрещено** переносить сущности одной feature «на вырост»;
- **запрещено** создавать пакет до первого такого типа;
- при добавлении типа — ADR update с перечислением владельцев.

До появления пакета общие типы не нужны — используйте порты и domain своей feature.

## Последствия

- `shared_domain` остаётся тонким kernel.
- Каждое добавление — осознанное решение, не scaffold.
